# 需求补充与教学闭环完成度核验

2026-09-11。黄山确认本轮先讨论需求与完成度，不改动前端 Demo。

**结论：教学闭环在功能与页面设计上基本完整，前端演示和后端基础已有实现；真实数据贯通的教学闭环尚未验收，两个赛题目前均不能认定完成。** 以下区分用户已确认需求、建议细则和代码实测。

## 1. 已确认：学生提交门禁

取消“学生自评分／预评分”待议项，改为提交门禁：学生交错作业，或规定三个任务只提交其中一个、两个时，退回补充；老师能看到该学生已尝试提交及异常状态，不能仍归为“未提交”。门禁不给学生生成分数，也不替代教师端 AutoGrader。

建议细则：

- 教师在实验要求中确认“必交任务清单”，检查作业匹配、任务覆盖和明确要求的附件。必交任务不等于所有采分点，答错、质量不佳仍交给正式评阅处理。
- 学生提交后先保存记录和原文件，再检查；通过则为“已提交／待评阅”，明确缺交则为“提交异常／待补交”，展示缺项和重新提交入口。
- 老师端显示学生、作业、提交时间、异常原因和补交进度。异常记录从“未提交”中单列，补交后保留先前尝试；未接受的报告不进入正式评阅和成绩统计。
- 解析失败、扫描不清或无法确定时，显示“检查失败／待确认”，允许重试或教师处理。系统读不出来，不能认定学生没有完成。
- 判定须依据真实报告内容，不能只靠文件名、固定示例或关键词数量。

建议流程：未提交 → 检查中 → 已提交／待评阅；发现缺项 → 提交异常／待补交 → 重新提交检查。检查服务故障单独记录。

承载于 P4 作业与报告、P5 实验设置、P6 评阅管理及 P7 报告详情，无需新页面。当前前端状态没有提交检查阶段，本项尚未实现。

## 2. 已确认：增加语音输入

为现场演示及日常使用增加语音输入，优先覆盖 DSH 对话和教师布置作业、实验内容。建议共用一套语音转文字能力：

| 顺序 | 位置 | 写入目标 |
| --- | --- | --- |
| 第一批 | P3 材料助手、P7 反馈助手的原生 DSH 输入框 | 当前对话草稿 |
| 第一批 | P5 作业／实验说明、教师补充要求与评分判据 | 当前编辑字段 |
| 后续补齐 | P3 备课说明、答疑卡长文本；P7 教师评语 | 当前编辑字段 |

交互为：点击麦克风 → 说话 → 停止 → 校正文字 → 发送或保存。保留已有文字，不自动发送问题、发布作业或确认成绩。显示录音状态与停止入口，切页结束录音；授权拒绝或转写失败时保留已有草稿和文字输入。

本次为语音输入，此前暂缓的连续实时语音对话不自动纳入。转写服务尚未选定；须在演示设备、浏览器和网络实录验证中文及 TCP、SYN/ACK 等术语。仅有麦克风按钮不算完成，本轮没有验收语音录入。

## 3. 原闭环是否基本完成

设计已覆盖：教师备课 → 提供材料 → 学生借助 AI 学习 → 完成实验报告 → 提交门禁 → AutoGrader 建议 → 教师复核发布 → 学生复习建议与教师教学建议 → 教师更新教学内容。

“AutoGrader → 学生反馈”需要经过教师确认；门禁在正式评阅之前。教学建议回到现有材料、答疑卡或实验要求编辑即可承接下一轮，不必另建模块。

| 层次 | 当前判断 |
| --- | --- |
| 产品闭环设计 | 基本完整；新增两项可由现有八类页面承载 |
| 前端交互演示 | 主要页面与模拟流程已完成，原生 DSH 已内嵌；门禁和语音尚未实现 |
| 后端工程 | 已新增存储、数据库、上下文组织、评阅状态、教师发布和统计；44 项现有测试通过 |
| 真实教学闭环 | 尚未完成：前后端未贯通验收，真实文件解析、图像传入和有效评分有缺口 |

最后一环需实际演示：教师依据真实失分统计修改材料或答疑卡、确认发布，学生获取更新内容。只显示“教学建议”卡片，尚不足以证明循环已经运行。

## 4. 两个赛题逐项判断

按用户给出的两题描述核对，不把功能名称或提交说明当作能力验收。

| 赛题能力 | 当前已有 | 尚缺的完成证据 |
| --- | --- | --- |
| 多模态教学：图文素材智能解析 | 文件落盘、原件预览／下载、上下文结构 | PDF/Office 正文和真实图片提取；现有路径仍有固定文本、合成图表描述 |
| 多模态教学：知识点结构化抽取 | 知识点字段、抽取请求和展示 | 实际课件生成正确知识点、定位真实来源；失败不能返回无关 TCP 示例 |
| 多模态教学：交互式答疑辅导 | 原生对话、引用草稿、答疑卡检索和问答接口 | 原始图片真正进入模型、当前材料与会话联通、多轮追问及来源正确性实测 |
| AutoGrader：报告自动解析 | 上传存储、提交实体、报告上下文结构 | 提取真实正文、代码和截图；空报告不能被描述成“内容完整、已核验截图” |
| AutoGrader：评分点逐项核查 | 评分表、状态机、逐项结果、程序求和、批量与重试 | 每项判定来自该报告证据；模型失败时不能靠固定扣分数组生成完成结果 |
| AutoGrader：成绩评语智能生成 | 建议分／评语结构、教师发布和反馈接口 | 实际模型输出的针对性、依据与评分有效性，以及师生端到端交付 |

**两个题目的功能结构都已搭建，但六项核心能力均有实际输入、输出或联调验收缺口。** 当前可以展示工程进展和标明样例的交互，尚不能宣称两个赛题已完成。

## 6. 建议的下一轮完成标准

先消除“读不到文件仍成功、没有证据仍给分”的兜底行为，再接通现有前后端，用同一门真实计算机课程完成：

1. 教师上传带图课件，真实提取正文与图像，核对知识点和来源。
2. 学生围绕真实图片问答与追问，引用可核对的页码和图。
3. 教师确认实验任务和评分依据；交错、缺任务、正常报告分别通过门禁验收，老师看得到异常和补交记录。
4. 合格报告进入逐项评阅，分数对应真实证据；失败保留失败状态。
5. 教师修改并发布，学生只见自己的已确认反馈，教师统计限于对应范围。
6. 教师依据结果更新教学内容，学生获取新内容；对话及实验说明的语音输入用实际录音走通。

这条真实链路通过后，才记录“教学闭环已跑通”；两个赛题仍分别按六项能力验收，页面数量和测试总数不代替验收。
