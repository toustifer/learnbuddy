# AutoGrader 产品交接与 v0.2 设计基线

更新：2026-09-19。代码基线：`1ac6a10`。本文用于接手产品、设计与开发，目标要求不代表已经实现。

需求依据为用户提供的 `D:\download\AutoGrader_PRD_v0.2.docx`（实际文件名）。原 Word 保持不变；本文替代之前 v0.1 交接稿的设计重点和优先级。详细实现差距见 [F1–F13 对齐表](AUTOGRADER_V02_ALIGNMENT.md)。

## 1. 三分钟理解产品

AutoGrader 面向教师，依据教师确认的实验评分标准阅读学生报告，找出证据、形成逐项建议，并集中呈现值得教师判断的问题。教师调整并确认后发布正式反馈，再汇总为班级教学洞察。

v0.2 的首要体验是：**点击评分项，报告定位并高亮依据；看见已覆盖与未覆盖要求；教师聚焦关注项，确认后看到班级共性问题。** 比赛呈现优先，但真实证据和可复跑能力不能由固定样例冒充。

当前已有课程、作业、Rubric、提交记录、评分接口、教师复核发布与统计基础。报告评分仍读取样例或固定描述，定位高亮、结构化覆盖缺失和关注队列尚未完成，不能宣称 v0.2 真实评阅闭环已经运行。

## 2. 相比 v0.1 的设计调整

| 方面 | v0.2 采用的要求 |
| --- | --- |
| 主用户 | 教师是主演示对象，学生提交与反馈证明闭环 |
| 核心页面 | 真实报告阅读器与评分面板并排，证据可定位高亮 |
| 教师价值 | 减少查找与重复核对，聚焦专业判断 |
| 结果表达 | 建议分、简短理由、证据、覆盖缺失、关注原因 |
| 演示终点 | 从单份评阅进入由正式结果形成的班级洞察 |
| 工程取舍 | 完整认证、大规模队列、完整版本回滚后置；已有能力保留 |
| 异常场景 | 保留真实失败处理和回归验收，不以模糊截图作为主演示亮点 |

原稿中强制每次改分填写理由、完整保留每次重试快照等建议，不作为已确认的 P0 细则。原稿混合内容判断与系统失败的枚举已废弃，采用第 6 节的分离设计。

## 3. 目标流程

教师确认实验与 Rubric → 学生上传真实报告 → 提交检查 → 显示实际解析结构和处理阶段 → 按评分项查证与判断覆盖 → 教师关注筛选、核对、调整 → 整体确认发布 → 班级洞察。

提交完整性与内容质量分开：缺文件、损坏、不可解析进入提交处理，不能解释为学生得零分。复杂缺任务自动退回与补交规则需单独定义，不作为首要演示场景。

## 4. 六个页面的交接

| 页面 | 当前基础 | v0.2 需要补齐 |
| --- | --- | --- |
| P1 作业配置 | 在线 Rubric 编辑和发布已有 | 结构化提交要求；证据要求与扣分档位配置待定 |
| P2 提交管理 | 名单、状态和批量入口已有 | 真实阶段进度、关注项数量 |
| P3 单份评阅 | 分数/评语编辑、证据文字、原件外链 | 左侧约 60%–65% 报告阅读器，右侧约 35%–40% 评分面板；证据定位高亮 |
| P4 教师关注队列 | 无对应实现 | 按 Review Item 组织跨学生关注队列 |
| P5 班级洞察 | 已发布分数、Rubric 失分率及薄弱项 | 至少一类真实问题聚合，确认发布后刷新 |
| P6 学生反馈 | 正式成绩与逐项反馈已有 | 与新评阅契约连通，保持发布前隐藏内部建议 |

## 5. 范围与优先级

**P0：** 一门真实实验课、4–6 项 Rubric；PDF/DOCX 报告上传解析；真实处理过程；逐项建议；证据卡、定位高亮；覆盖缺失；教师关注模式；修改与确认；至少一种班级洞察。

**P1：** 批量评阅与班级进度、正文与图表矛盾对照、更完整问题聚类、学生反馈体验、Rubric 编辑体验优化。已有批量和学生页面继续复用。

**P2 或后续：** 完整认证与细粒度权限、大规模并发、复杂格式、完整历史与回滚、跨学科泛化、复杂查重、知识图谱。PRD 将全自动发布列为后续方向，本版仍以教师确认发布为规则。

## 6. 数据和状态

以下属于 v0.2 目标契约，不是当前接口字段。

- Review 保存一次评阅；Review Item 对应一个 Rubric 项，包含建议分、判断、理由、证据、覆盖状态及教师最终决定。
- 内容判断 judgment：satisfied / partially_satisfied / not_satisfied / professional_judgment。
- 评阅状态 reviewStatus：pending / processing / completed / needs_review / failed。
- 关注分类：表现明确、值得关注、需进一步处理；分类规则待定。
- 每项建议关联可定位证据，或明确未覆盖要求。总分由程序计算；教师最终分与说明持久化；整体确认前内部建议对学生不可见。

当前成绩仍放在 submissions 的 grades/summary/history 中；状态为 submitted/grading/review/published/failed。需要兼容迁移，不能直接替换枚举。特别是 completed 只代表处理完成，不等于已发布。

本机启动时没有配置模型密钥。在线评分请求使用 strictLLM，模型失败会抛错；其他路径仍可能返回模拟或规则结果。严格模式没有消除报告提取中的固定内容。页面、接口、测试通过不能证明实际评分质量。

## 8. 建议交付顺序

1. 接通真实报告上传与解析，替换固定报告描述，生成真实页码、元素和图片引用。
2. 将解析阶段、逐项判断、覆盖缺失、定位高亮做成单份报告旗舰体验。
3. 增加单份关注筛选与跨学生关注队列，接入现有修改和整体发布。
4. 用正式评分项聚合至少一种班级洞察，确认发布后刷新。
5. 扩展批量规模与矛盾对照；完整生产化工作不抢占主链路。

此顺序是实施建议。教师仍需确认关注分类规则、Rubric 子要求与档位、DOCX 分页、证据高亮方式、班级指标口径和批量规模。

## 9. 演示与验收

主演示采用 A 高质量报告、B 缺少关键解释的报告；C 内部矛盾为可选。坏文件、无密钥、模糊图片作为回归测试。PRD 中 40 份及 32/6/2 等数字是示意，不是当前实际结果。

必须能展示真实证据定位、覆盖差异、教师调整保存、正式结果聚合，并在更换真实报告后复跑。系统失败不产生假分数。教师修改反向校准未来评分属于后续方向，不在本轮承诺中。
