## 一、项目背景与比赛目标

1. **项目定位**：
   - 参加面向高校学生与教师的创新/AI竞赛。
   - 整合两个核心方向：**多模态教学智能体** 与 **实验报告/作业自动批阅（Auto-Grader）**。
   - 打通「备课与课件辅助 -> 学生自主学习/答疑 -> 作业/实验布置 -> 智能批阅与评分 -> 学情反馈与教学改进」的教学闭环。
2. **比赛策略与导向**：
   - **最高性价比与演示优先**：比赛核心在于高完成度、亮眼的现场功能演示、流程视频与真实说服力的案例，无需过度打磨全量商用细节。
   - **复用现有资产**：复用成熟工具（如 DeepSeek Harness、现有团队沉淀组件），但紧贴比赛评分维度，不被已有包袱束缚。
   - **拒绝纯“AI 套娃”**：
     - 评委反感“上一阶段 AI 瞎编、下一阶段 AI 接茬”的不可靠闭环。
     - 强调“**人类教师专业干预 + AI 辅助增强**”，体现真实教育严肃性与落地价值。

---

## 二、产品形态与核心功能

1. **双端形态**：
   - **学生端**：可独立运行，支持围绕课件/资料的伴学、自测、问答与实验报告提交。
   - **教师端**：可独立运行，支持课程/实验资料配置、问答模板预制、报告批量自动批阅与学情统计看板。
   - **完全体闭环**：两端协同形成教学全链路闭环，评委看全局，展示时可单点深挖。
2. **课件与问答预制（Teacher-in-the-Loop）**：
   - 教师借助 AI 辅助，预先提炼学生常见误区、高频疑问并提供标准讲解/解答模板。
   - 学生提问时优先命中权威预设，再辅以多模态 AI 解答，既快又准，有效规避幻觉与 AI 循环。
3. **实验报告/作业批阅（Auto-Grader 核心红线）**：
   - **严格定位为批阅、查验与反馈**，而非“帮写/代写（Auto-Writer）”，坚决避开学术诚信与作弊红线。
   - 多模态批阅：结合图表、数据和步骤截图进行多模态审核评分与针对性诊断建议。
4. **功能模块化（Skills / Plugins）**：
   - 课件解析模块（Multimodal Parsing）
   - 知识库与问答检索模块（Curriculum Q&A）
   - 实验报告规则与多模态评分模块（Auto-Grader）
   - 学情统计与诊断分析模块（Analytics）
   - *语音输入*：评估链路延迟与稳定性，作为加分项而非阻断性主干。

## 三、技术选型与实现方案

1. **底层框架**：
   - 基于 **DeepSeek Harness (DSH)** 智能体架构。
   - **优先采用插件/扩展方案（DSH Plugin / Web App 模式）**，不直接暴力魔改底层内核，保证升级灵活性、低维护成本与可定制的 UI 交互。
2. **模型选型**：
   - 推荐选用多模态模型（如 **GLM-5.3-Flash / 多模态高效模型**），兼顾多模态理解（图表/公式/课件）、超低延迟响应与高性价比成本，适合演示与压测。
3. **开发分工与链路**：
   - 需求文档生成 -> 代码脚手架与后端开发 -> 前端与视觉交互优化。

---

## 四、关键风险防范

1. **学术诚信敏感点**：Auto-Grader 页面与交互文案必须体现“诊断报告、评语建议、查重比对”，严禁出现任何一键润色、代写报告的引导。
2. **演示可靠性（网络与时延）**：现场演示或录制视频中，关键路径（如大文件解析、报告批阅）需做进度反馈或异步占位，复杂链路备好离线 Mock / 兜底样例，杜绝因外部网络故障翻车。
