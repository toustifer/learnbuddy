## 一、核心功能决策与边界厘定

1. **功能二选一决策**：
   - 在“多模态教学智能体”与“Auto-Grader（自动评分）”两个方向中，**一致决定将“多模态教学智能体”作为最核心重点功能优先做好**，确保 Demo 阶段体验完整闭环；Auto-Grader 作为高价值配套功能稳步推进与完善。
   - **决策理由**：
     - 黄山指出：教学智能体在用户交互体验、直观视觉呈现和比赛评委答辩冲击力上更占优势，更易获得正向反馈。
     - ostrich hero 评估：教学智能体场景完成度更高、扩展上限大。
2. **功能边界与红线**：
   - **多模态教学智能体**：以 DSH Plugin 形式呈现，作为学生围绕课件与实验材料自主学习的启发式辅助工具；提供思维线索、原理解析、排错提示与图表溯源，**严禁直接代写代做实验作业**。
   - **Auto-Grader**：用于教师端自动解析实验报告、逐项比对评分准则（Rubric）、计算小分与生成建设性诊断评语；必须保留**教师手动复核与确认机制**。

## 二、产品六步完整闭环流程

围绕教育教学实际链路，打通闭环：

```text
[1. 教师AI辅助备课] ──> [2. 课件材料结构化分发] ──> [3. 教学智能体自主学习(核心)]
        │                                                           │
        ▼                                                           ▼
[6. 学情分析与教学改进] <── [5. Auto-Grader自动批阅与教师复核] <── [4. 学生独立撰写实验报告]
```

1. **教师结合 AI 辅助备课**：AI 辅助提炼核心考点、高频误区，预制高置信度“教师答疑卡”。
2. **学生获取课件材料**：以课程为单位组织，教师统一上传，学生在线预览或下载原件。
3. **学生借助 AI 自主学习（核心功能）**：通过伴学智能体就课件图文、时序图、抓包图提出疑问，智能体优先命中教师答疑卡，并进行启发式引导与图表溯源。
4. **学生完成实验报告**：学生根据实验要求独立动手撰写报告；遇到疑难可在伴学舱追问，但智能体严禁直接输出实验报告文本。
5. **Auto-Grader 批阅与教师复核**：学生提交报告，Auto-Grader 多模态逐项核查打分并生成评语；增加**“一键整体确认”复核按钮**，强化 Teacher-in-the-Loop 的严肃性，确认前成绩对学生严格脱敏。
6. **学情诊断与教学反哺**：系统汇总多份报告薄弱项，输出班级/课程知识点失分大盘，反哺教师开展针对性讲评与二次备课。

## 三、技术架构演进：Agent 友好与 MCP 规范

1. **数据存储结构化（Agent-Friendly & MCP-Friendly）**：
   - 底层数据（课程、课件知识点、教师答疑卡、作业 Rubric、批阅快照、学情指标）必须统一结构化存储（SQLite/JSON）。
   - 杜绝非结构化私有黑盒，为全局 Agent 与外部 MCP 客户端提供标准清晰的访问契约。
2. **全局 AI Agent 与多 Agent 协同**：
   - 计划在平台中引入全局调度 Agent，能跨课程综合拉取学生的学情数据、历史提问、课件知识点与作业状态，提供全局学习诊断与平台导航。
   - 全局 Agent 核心护城河在于能够安全读取内部结构化业务数据，而非通用 LLM 的纯聊天。
3. **MCP (Model Context Protocol) 与 Workbuddy 集成**：
   - 对齐标准 MCP 接口协议，让 Workbuddy 或外部 Agent 能够直接通过 MCP 连接平台，调用课件检索、提交查验与答疑接口。
   - 用户既可以使用平台内置的 DSH 教学智能体，也可以无缝桥接 Workbuddy 进行多端伴学。
4. **多格式文档解析能力评估**：
   - 课件伴学与报告批阅均依赖高质量文档提取（PDF、DOCX、PPTX、表格、内嵌图片）。
   - 评估已有成熟方案（如微软 Docs-to-Markdown、AnyDoc 平台原生解析等），结合团队沉淀选型，兼顾图片多模态内联与异常容错。
