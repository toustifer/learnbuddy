# LearnBuddy 开发分工与 Demo 验收计划

版本 1.0｜2026 年 9 月 17 日｜目标：9 月 26 日前形成可以实际演示的教学闭环。

多模态教学智能体优先保证质量，其余环节做到真实、清晰、可恢复。黄山已确认平台内全局 Agent 与外部 MCP 都要跑通最小示例。验收按真实行为和来源判断，不按页面数量、接口数量或自动测试数量判断。

会议确定本周六前完成方案、周六开始开发，并在 26 日前闭环。以 9 月 16 日会议日期换算，周六为 9 月 19 日；以下具体每日安排属于建议排期，不是已经发生的进度。

## 3 任务包和依赖

### W01 开发环境与身份基础

负责人建议嘉俊。确认主分支、客户端与服务器工作流；建立测试账号及课程权限；给网页、文件读取、DSH 和 MCP 提供同一身份来源。交付可复现启动和连接步骤、跨用户拒绝访问的结果。它是后续外部接入的前置条件。

### W02 统一文件解析和版本

负责人建议柳穿鱼，嘉俊共同评审。复用现有保存与解析实现，补真实图像、OCR 和来源锚点，新增文件版本与任务状态。交付解析能力矩阵、真实样本结果和错误分类。伴学与报告均使用同一解析结果契约。

### W03 课程伴学与教师答疑卡

负责人建议嘉俊，黄山负责界面。接课程会话、材料范围、实际图像、发布卡检索和引用定位；落实允许解释步骤与示例代码但不代做实验、编造结果、生成整份报告的边界。交付材料内提问和切课恢复演示。

### W04 提交检查与 AutoGrader

负责人建议柳穿鱼。实现必交检查、尝试历史、真实评分、失败恢复、整批确认及学生投影。交付通过、缺项、交错、解析失败和重试案例；移除生产评分中的固定证据、默认评分表与样例分数兜底。

### W05 全局 Agent 与 MCP

负责人建议嘉俊，黄山负责入口和契约。先实现 03 中的最小只读查询，复用到内置 DSH 全局模式和外部客户端。交付学生跨课程任务建议、教师课程作业概览和越权拒绝的真实调用记录。

### W06 教学反馈与闭环验收

柳穿鱼负责统计和建议，黄山负责体验验收，嘉俊负责部署。实现 AI 建议和已复核双口径，教师采用建议后进入原编辑位置。交付完整闭环记录与可恢复演示环境。

W01、W02 应先稳定；W03 和 W04 可在统一契约下分别推进；W05 可与它们同步，但不能跳过身份校验；W06 依赖真实提交和评分数据。每项任务完成后更新 05 中的实际状态和代码指针。

## 4 演示资料准备

建议沿用现有计算机网络场景作为候选，以实际课件为准。黄山准备可展示的教师课件和教学目标；柳穿鱼准备相应实验要求、评分表及可核对的报告；嘉俊检查文件解析与服务器资源。正式演示主题及素材须由团队在方案冻结时确定，不把当前种子 TCP 内容当作真实教师材料。

最低样本建议为：一份含图 PPTX、一份含图或扫描页 PDF、一份含表格 DOCX、一张可读图、一份 XLSX/CSV；报告包含正常、缺一项、交错作业、内容完整但答错、无法解析五类。可以人工构造并标记测试样本，不使用真实学生私人数据或虚构真实成绩。

单份课件应有可人工核对的图像细节和来源位置；至少准备一张经教师确认的答疑卡和一个未命中问题。真实模型回答、真实文件读取与测试替身分别记录。

## 5 核心验收用例

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| A01 | 教师上传课程资料，学生登录读取 | 同课程学生可读下载，私人文件与其它课程被拒绝 |
| A02 | 读取含图课件并询问图中细节 | 模型实际获得图像，回答依据可回到正确材料版本与位置 |
| A03 | 对未读取或模糊图片提问 | 明确不能核验的部分，不生成确定图像结论 |
| A04 | 发布、命中、停用教师卡 | 仅确认发布的卡带教师提示；停用后不再作为现行依据 |
| A05 | 连续追问并快速切课程 | 新课程不收到旧课回复；返回旧课可恢复自己的上下文 |
| A06 | 请求示例步骤或代码，再请求代写完整报告 | 前者可教学解释；后者不生成可提交成品或伪造实验数据 |
| A07 | 提交完整但答错的报告 | 完整性检查通过，错误交给评分；学生未收到预评分 |
| A08 | 缺项或交错报告后补交 | 清楚列缺项，教师看得到尝试，旧报告和原因保留 |
| A09 | 上传无法解析的报告 | 技术失败与缺项分开，可重试或人工确认，不记为未提交 |
| A10 | 无评分表或模型不可用时评阅 | 明确失败或等待依据，不给默认评分和固定证据 |
| A11 | 对真实报告评分 | 每项有合法分值和真实证据，总分由程序求和，能说明不确定项 |
| A12 | 教师未确认与确认后分别查看学生端 | 未确认时不返回分数和详细评语；确认后本人可见，他人不可见 |
| A13 | 教师不点击确认仍查看教学反馈 | AI 建议口径可用并标明未复核；不会冒充正式成绩 |
| A14 | 教师采用建议修改并发布答疑卡 | 学生能获得新版；旧回答仍可追溯原版 |
| A15 | 内置全局 Agent 查询学习或教学概览 | 使用当前账号实际数据，附范围与时间，无依据不推断掌握度 |
| A16 | 外部客户端通过 MCP 执行同样查询 | 实际列出并调用工具，结果与网页同权限，不靠人工粘贴数据库 |
| A17 | 伪造用户 ID、跨课引用、直接请求他人文件 | 网页 API、文件、DSH、MCP 均拒绝；隐藏按钮不能作为通过依据 |
| A18 | 重复提交、重试任务和并发确认 | 不生成重复有效记录；冲突有明确提示，原件和草稿保留 |

这些用例覆盖新版需求。旧的自动测试继续作为回归检查，但 A02、A11、A14、A16 等必须有真实输入、模型或客户端证据。

## 6 录制时的演示顺序

建议控制在一条 8 至 10 分钟链路：教师展示课件与已确认答疑卡；学生在图旁提问并点回来源；展示一次补交；教师展示真实评分、未复核统计及整体确认；学生展示自己可见的反馈；教师采用建议更新卡片；最后分别展示内置全局查询和 MCP 查询同一平台数据。

处理耗时可以事先完成，但必须说明哪些任务预先运行，并保留原件、任务 ID 和结果证据。准备失败演示和恢复入口，不能用剪辑隐藏模型或权限仍未接通的事实。

## 7 验收记录格式

每个用例记录：用例编号、日期、代码提交、部署版本、浏览器或客户端版本、测试账号角色、输入文件 hash、关键任务和会话 ID、实际观察、预期差异、证据路径、通过或失败、责任人。对话与报告证据保存在受控项目位置，IMA 只放脱敏摘要和必要操作说明。

完成判定为全部主链路用例通过，且未解决问题不影响真实图文理解、身份隔离、学生提交、教师复核和反馈回流。正式演示前记录已知限制与降级方式；未经实际验证的格式、语音、模型和客户端能力不能出现在“已完成”列表。
