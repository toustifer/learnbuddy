# LearnBuddy 工程现状与开发协作指南

版本 1.0｜2026 年 9 月 17 日｜供团队从 IMA 接手现有 Git 项目、开发客户端与服务器工作。

现有项目已经具备新版前端、课程与文件接口、DSH 内嵌对话和评分服务骨架。继续开发应基于这些代码增量完善，优先解决真实文档与图像读取、报告评分真实性、身份隔离、MCP 和闭环联调。本文件区分当日仓库核对、历史服务器验收和仍待完成的操作指南。

| 范围 | 当前证据 | 开发时要补齐的内容 |

| 报告解析 | extractReportContent 仍会依据文件元数据或文件名生成固定正文与图示 | 接入真实报告解析，移除生产路径中的固定证据 |

| 认证 | 当前登录与多个接口依赖请求中的用户标识；部分路径不验证真实密码或令牌 | 统一可信身份和课程权限；REST、文件读取与 MCP 同步修复 |
| MCP 与全局 Agent | 当前源码目录未见本包所列 MCP 工具实现 | 新增适配器和最小全局查询，进行真实客户端调用 |

## 4 现有与拟新增接口

现有接口包括 auth/login、materials、materials/upload、materials/:id/context、files/:id/view 与 download、qa/cards/search、qa/ask、dsh/session-context、dsh/quote、dsh/message、grader/grade-submission、grader/batch、grader/retry、grader/review-publish、analytics/assignment/:id、analytics/course/:id，以及主分支新增的 courses、assignments、submissions 列表和提交接口。

teaching.js 另有 workspace 汇总、创建作业和更新作业。开发者应以实际路由注册顺序检查行为，不要只读 docs/API.md 的端点总数；该文档原先主要覆盖 api.js。

本文档包中定义的版本读取、统一 job、提交检查、全局概览和 MCP 工具为拟新增或需改造能力，不能直接假定存在。保留旧端点时，由兼容层映射到统一服务，避免同一报告在两条路由产生不同结果。

## 5 本地启动和验证

使用 Node.js 22.19 以上或 24；建议团队统一 Node 24。项目使用 node:sqlite，系统旧 Node 20 不满足后端运行需要。按当前 lockfile 安装依赖；解析引擎含原生绑定，需在目标操作系统安装，不能直接复制另一台机器的 node_modules。

在新的开发副本中执行：

```sh
git clone https://github.com/toustifer/learnbuddy.git
cd learnbuddy
git switch main
git pull --ff-only
git switch -c feat/your-task-name
cd plugins/dsh-plugin-learnbuddy
npm ci
cd web
npm ci
npm test
npm run build
npm run build:dsh
cd ..
npm test
```

分支名替换为当前任务约定名称。已有工作目录先看 git status；存在未提交工作时不要重置或覆盖。单纯查看前端可在 web 下 npm run dev；本机 DSH 按 web/dsh-ui/README.md 的隔离预览步骤 setup:dsh、dev:dsh 启动。真实在线 API 与模型需要本机授权配置，不能把服务器生产凭据放进文档。

真实数据验收使用 VITE_DATA_MODE=live 和 VITE_API_BASE 指向测试网关。模拟模式必须有明显标记，不能用模拟数据完成真实闭环验收。DSH 当前仓库配置引用 0.1.5-rc.1；首次接手仍需核对实际安装版本及插件 API。

9 月 13 日历史合并验证为 57 项前端测试、219 项插件测试和两种构建通过。这些是当时版本的测试记录，本次编写文档未重跑，也不把它们标为新需求验收通过。

## 6 LearnBuddy 与 IMA 开发交接

1. 将本包六份 Markdown 正文和导读导入团队 IMA 开发知识库，知识库内保留版本与功能编号。
2. 在 LearnBuddy 中选择团队知识库，使用导读提供的检索问题确认能找到正确文档和版本。
3. 启动一个范围明确的开发任务，先检索需求，再读取实际仓库；不能仅凭知识库里的代码描述修改。
4. 工作结束后保存任务记录：采用的文档版本、代码提交、改动、测试、现场验证、未完成项和下一位接手人。
5. 更新对应 Markdown 文件；在 IMA 替换旧版或明确归档，避免多个版本同时被当作现行要求。

上述步骤是交接流程，不是已经完成的客户端实测。LearnBuddy 的具体 IMA 菜单位置、SSH 能力和 MCP 配置方式，由嘉俊用实际客户端验证后补截图及操作说明；不同客户端的能力不能根据名称推断一致。

## 7 Git 多人协作

建议每项任务一个分支和一个 PR，PR 写明功能编号、行为变化、涉及接口与迁移、验证结果。接口或数据契约修改先同步给依赖方，再并行修改页面；文档中拟新增接口不能直接当作已部署接口调用。

任务开始时记录基线提交；提交前检查 diff，排除 .env、密钥、数据库、上传文件与 DSH 会话目录。推送被拒绝时先读取远端新增提交，合入并处理冲突，保留双方有效改动；不强推覆盖队友工作。测试通过后由团队约定的合并人处理主分支。

原型、测试、真实模型调用和线上部署分别记录。不为了展示使用某个开发工具而修改已有开发历史或来源。

嘉俊补充的 SSH 操作指南至少应包含：开发客户端如何连接、实际账号与工作目录、密钥如何在本机配置、连接成功证据、只读检查与开发操作范围、如何使用任务分支。私钥与令牌不进入 IMA；公开操作说明使用别名或占位符。

部署顺序建议为：记录服务器代码与进程状态 → 保存未提交改动和数据备份 → 生成独立发布目录 → 安装目标平台依赖和迁移测试副本 → 在测试端口验证 → 切换对应进程 → 验证原入口、数据和 WebSocket → 保存发布与回退记录。旧数据库备份不能覆盖发布后新产生的报告。

历史回退命令以仓库 docs/DEPLOYMENT-2026-09-12.md 为准，执行前核对实际目录与进程。保持网关的 DSH Host、Origin 与会话转发规则，公网源配置修改后重新验收。网站能打开不代表模型、评分、认证或语音已可用。
