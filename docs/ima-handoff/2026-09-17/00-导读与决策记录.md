## 使用规则

阅读顺序为 00 → 01，再按任务读取 02 至 06。每个功能都有固定编号，任务、提交与验收记录沿用该编号。标为“会议决定”的内容用于判断产品方向；标为“实施建议”的接口、字段、阈值和日期安排需要团队评审，不能当成已经实现的能力。

同一主题发生冲突时，优先采用黄山最新明确决策，其次是本包中标明已确认的会议决定；历史文档用来追溯。代码决定当前实现事实，不能自行推翻产品要求。旧文档中的模型名称、未合并 PR 状态和服务器状态均须结合日期理解。

## 黄山已确认的五项决策

黄山于 2026 年 9 月 17 日在当前对话逐项确认，以下结论已同步到六份文档。具体字段、接口和实现步骤仍属于可评审的技术方案。

| 编号 | 已确认决策 | 实施影响 |
| --- | --- | --- |
| D1 | 只检查交错作业、必交任务和附件是否齐全 | 不做学生预评分，答错和质量问题交正式评分 |
| D2 | 教师确认后，学生可看自己的具体分数、详细评语和依据 | 确认前由服务端移除敏感评分字段及历史泄漏 |
| D3 | 整体确认记录教师已复核，不阻塞评分、统计和教学建议 | 后台处理与复核状态分开；教师建议口径标明未复核 |
| D4 | 平台内全局 Agent 与外部 MCP 均跑通最小示例 | 两种入口复用统一业务数据和角色权限 |
| D5 | 可以解释步骤、给示例代码；不代做实验、编造结果或生成整份可提交报告 | 技能提示、工具权限和验收用例采用同一边界 |

D2 与 D3 同时生效：不确认也能继续评分和生成教师建议；学生具体成绩仍需教师确认后可见。后续修改决策需记录日期和影响文档，更新版本并替换 IMA 中的旧版。

导入后，在 LearnBuddy 中选择该知识库，分别询问：重点功能是什么；教师能否读学生私人聊天；报告解析目前有哪些缺口；D2 的成绩展示条件是什么；MCP 的用户身份从哪里取得；服务器目前是哪次验收记录。回答应引用本包对应文档，保留日期、决策和验证边界。

“请先从 IMA 读取《LearnBuddy 开发文档包导读》和与本任务相关的文档，列出引用的版本及未决事项。然后读取 Git 仓库当前代码，确认已实现与缺口。围绕指定功能编号提出最小改动并执行已授权工作；遇到会改变产品边界的未决事项交给黄山决定。完成后给出代码版本、真实验证结果和仍未验证的部分，并更新交接记录。”

开发记录如实标明实际使用的工具和已有代码来源；导入 IMA 是知识交接，不改变历史开发事实。
