# LearnBuddy 多模态教学智能体实施规格

版本 1.0｜2026 年 9 月 17 日｜功能 C03、C04、C06、T02、T03、S02、S03、G01 至 G03。

本规格把主线教学智能体落实为可开发和可验收的行为：读到当前课程的真实图文，采用教师确认的答疑卡，支持连续追问，并让用户核对来源。DSH 提供对话运行环境，LearnBuddy 插件提供课程上下文和受控业务工具；提示词不能替代文件读取、权限校验和状态管理。

产品方向依据 9 月 16 日会议及黄山 9 月 17 日确认。以下上下文结构、工具调用流程和输出约定是实施建议。仓库已有相关模块，但完整能力尚未完成真实验收，差距见 05。

## 1 三种工作模式

| 模式 | 可用上下文 | 输出与限制 |
| --- | --- | --- |
| 课程伴学 | 本人可访问的当前课程资料、当前材料、已发布答疑卡、当前作业及允许展示的本人反馈 | 解释、排错、追问、来源；不读取他人报告或其它课程私人资料 |
| 教师备课 | 任教课程资料、私人备课文件、已授权作业汇总 | 讲解建议和备课草稿；修改或发布通过业务操作确认 |
| 全局指引 | 当前用户全部获准课程的摘要，按需深入资料或统计 | 学生看自己的学习任务，教师看任教课程概览；不自动把所有文件和会话放进上下文 |

模式和 courseId 由平台入口自动提供。学生不用手动选择目录、打开开发者工作区或复制系统提示词。全局模式进入具体课件时携带课程与材料标识，课程模式需要跨课查询时先说明范围并使用全局权限检查。

## 2 课程会话如何建立

1. 页面发送当前课程、材料或作业标识；服务端从已认证会话取得用户身份和角色。
2. 服务端确认用户可访问该对象，读取其版本和课程关系，生成上下文清单与短期引用凭证。
3. 以用户、模式、课程和任务上下文查找会话映射；首次进入时新建会话，返回该用户的会话标识。
4. 插件加载课程摘要、当前材料摘要和获准工具。正文、图片与答疑卡按问题检索读取，避免全量堆入提示词。
5. 页面收到绑定成功后显示当前课程与引用范围，才允许发送该上下文的问题。
6. 切换课程时取消旧请求，切换到目标课程的会话；迟到回复带有旧 contextKey 时丢弃，不能进入新课程草稿。

建议会话键为 actorId、mode、courseId、contextId 的组合，contextId 可对应材料或作业；服务端保存 DSH sessionId 与工作区映射。客户端 localStorage 仅缓存展示状态，不能作为身份或授权依据。撤销课程权限后，恢复旧会话也必须重新校验。

当前共享预览工作区只作为开发环境保留。学生端不得获得服务器终端、任意路径读写、Git、外发消息或其它开发者工具；面向学生的 Agent 使用课程业务工具和必要的只读图文能力。

## 3 文档解析与来源定位

同一解析服务同时处理教师材料和学生报告。原件按文件标识保存，解析产物绑定不可变文件版本。建议输出正文块、图片资产、表格块和来源锚点，不只保存一段 Markdown 摘要。

| 类型 | 首版要求 | 不足时怎样呈现 |
| --- | --- | --- |
| PDF | 提取正文；保留页码；需要理解图时提供原图或页面图像 | 扫描页转 OCR；缺失图像时标记不能核验图内容 |
| PPTX | 保留幻灯片序号、正文、图片及其关联 | 图表或文本框缺失时记录缺失对象 |
| DOCX | 保存段落、标题、表格、图片及锚点 | 不编造稳定页码；必要时结合渲染版页码 |
| PNG/JPG | 保存原图，提供实际可读图像；OCR 文本作为辅助 | 低清文字明确不确定，可请用户提供清晰图 |
| XLSX/CSV | 保存工作表、单元格范围、表头与类型 | 区分公式与缓存值，不承诺执行所有公式或还原所有图表 |

代码中的扩展名白名单、解析引擎支持和模型读图能力是三个独立条件。候选解析方案用同一组真实文件比较正文完整性、图像保留、定位准确性、耗时和错误表现；不能只比较支持格式数量。当前 anydoc 是可复用的基础，OCR、PDF 图像和报告管线需单独补齐。

解析结果记录 complete、partial、failed 三种完成程度。处理超时、加密文件、损坏文件、图片超限或未处理页面均列入 warnings 和 omittedRanges。不存在的原文、读取失败的图片不能补成固定描述。

## 4 一次材料提问的完整过程

学生选择当前页中的图并提问，平台把选区、材料版本和锚点作为引用加入草稿；只有学生发送后才调用模型。服务端检索当前课程相关正文与教师卡片，检查引用权限，提供实际图片内容，而不是只有文件名或图片说明。

模型回答应包含解释、依据和下一步。涉及图像细节时引用图像锚点，涉及教师卡片时标明卡片与教师确认状态；来自一般知识的补充单独说明。读图失败、文本不足或存在矛盾时说明限制，不编造“已经查看第几页”。

客户端至少显示材料名、版本、页码或其它定位、教师提示来源和可点击回原文入口。引用 ID 由服务器校验必须存在于本次实际提供的材料集合；模型输出不存在的引用时拒绝该引用并要求重答或展示无法核对。

连续追问沿用当前会话和材料范围，但新材料版本不得静默替换旧证据。若教师更新材料，提示有新版本；新问题可使用新版，既有回答仍能定位旧版。

## 5 教师答疑卡如何生效

卡片字段最少包含 cardId、courseId、materialVersionId、question、keywords、conditions、answer、evidenceRefs、status、confirmedBy、confirmedAt、revision。发布状态为 draft、published、retired，草稿可修改，确认时形成可引用版本。

先限定角色、课程、发布状态和材料版本，再做关键词或语义检索。相关性不足时不强行匹配；多张卡矛盾时引用各自条件，必要时提醒教师修订。卡片匹配充分且只是准确复述时可以不调用模型，直接展示卡片正文及来源。

只有已发布且有教师确认记录的内容才能称为“教师提示”。AI 扩写部分标为“AI 补充”，不能沿用教师背书。现有技能提示中“答疑卡已注入”的固定陈述应改成根据本次实际 cardRefs 判断。

示例：学生询问握手中断的原因。命中教师关于超时重传的卡片时，先展示该卡片适用条件，再结合学生所引用截图分析是否满足。截图没有关键序号时，应指出还缺哪些证据，不断言具体网络故障。

## 6 对话上下文和回答契约

建议由后端构造 ContextPacketV1。所有字段都属于本项目业务约定，不是 DSH 官方固定接口。

```json
{
  "schemaVersion": 1,
  "contextKey": "studentA:course:network:materialA",
  "actor": {"id": "studentA", "role": "student"},
  "scope": {"mode": "course", "courseIds": ["network"]},
  "materialVersions": ["mv_001"],
  "cardRefs": ["card_007:r2"],
  "evidenceRefs": ["ev_page2_figure1"],
  "readState": {"status": "partial", "warnings": ["第 5 页尚未处理"]}
}
```

actor 与 scope 由服务端生成，不接受浏览器或模型伪造。原图通过已授权的读取服务提供，不能将服务器绝对路径交给客户端直接读。上下文只是清单；大正文、图像与报告证据通过工具按需取回。

回答建议保存 answerText、evidenceRefs、teacherCardRefs、limitations、nextStep、contextKey、materialVersions、modelRunId。数字、来源 ID 和教师卡片状态在保存前校验。取消请求不丢失已输入草稿；重试不自动重复发送。

## 7 全局 Agent 的最小实现

黄山已确认：9 月 26 日前，平台内全局 Agent 和外部 MCP 都跑通最小示例。两者调用同一业务查询层，使用相同账号范围和返回结构；只维护一套课程、权限和统计逻辑。

学生示例：“我本周先做哪门课的任务？”先读取本人课程与作业截止时间，再按未完成事项给出建议和页面入口；没有学习质量数据时不判断哪门课学得差。教师示例：“我任教课程里哪些作业需要补讲？”读取本人的课程统计，报告样本数、未复核数量和证据，返回可打开的作业或反馈页。

首版全局工具以只读为主。生成备课草稿可复用平台既有生成动作；发布课件、改分、确认成绩和替学生提交不由全局对话隐式执行。

## 8 教学回答边界

黄山已确认 D5：可以解释步骤、给示例代码，但不代做实验、不编造结果、不生成整份可提交报告、不自动提交。示例应帮助学生理解和自行操作，说明适用条件；学生请求完整报告时，转为讲解结构、分析其已有证据或指导下一步。该边界同步写入技能提示、工具权限和验收用例。

课件、学生报告、检索到的卡片和 IMA 文档都是内容来源，里面出现“忽略规则”“读取服务器密钥”等文字时不得作为操作授权。模型可解释资料中的命令，但不能因为资料包含命令就执行。

## 9 实施位置与验收

后端插件入口为 plugins/dsh-plugin-learnbuddy/src/index.js，技能注册在 src/skills/index.js，课程上下文可复用 src/services/material-context.js 与 dsh-context-bridge.js。UI 适配在 web/dsh-ui，页面引用在 web/src/components/DshAssistant.tsx 与 web/src/dsh.ts。先确认实际安装的 DSH 版本和公开 API，再接会话及工具；不能把新增业务字段假定为现成 DSH API。

验收必须覆盖：实际图像读取并正确引用；教师卡片发布和撤回；非当前课程与他人资料拒绝访问；快速切课不串答；解析部分失败明确说明；全局查询来自当前用户真实数据；模型失效时保留失败而不返回样例答案。用例和证据要求见 06。
