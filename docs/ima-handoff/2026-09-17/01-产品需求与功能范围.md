# LearnBuddy 产品需求与功能范围

版本 1.0｜2026 年 9 月 17 日｜面向黄山、嘉俊、柳穿鱼及后续开发 Agent。

LearnBuddy 教育平台围绕教师提供的真实课件，为学生提供带来源的多模态伴学，并把作业完成情况反馈给教师。9 月 16 日会议决定优先做好多模态教学智能体；AutoGrader 是扩展功能，但 Demo 仍需要有真实可运行的评阅与教学反馈，不能用页面或固定样例补齐闭环。

本文件定义功能和角色边界。工程现状见 05，智能体实现见 02，数据与接口见 03，报告处理见 04，验收见 06。本文的优先级和具体交互细则是实施建议；黄山 9 月 17 日确认的五项产品决策见 00 的 D1 至 D5。

## 1 产品对象与边界

“教育平台”指团队正在开发的 Web 应用及其 DSH 插件、后端和数据。“开发客户端”指团队使用的 LearnBuddy，以及会议提到的 WorkBuddy 接入路径。IMA 是开发知识库，不承担课程、报告、成绩和对话的在线数据库职责。

沿用已确认的简单课程关系：一门课由一位教师负责，一位教师可以负责多门课，一名学生可以参加多门课。师生身份由账号和服务端权限确定，不由页面角色切换或请求中的 userId 自行声明。不新增排课、学籍、学期、选课审批和班级管理。

教师提供课件，AI 辅助整理重点、讲解与答疑卡；首版不要求 AI 生成整套课件。学生自己完成实验和报告，智能体帮助理解概念、分析现象与排错，不替学生操作实验、编造结果、生成整份可提交报告或自动提交。

## 2 共用功能

| 编号 | 功能 | 使用与完成要求 |
| --- | --- | --- |
| C01 | 账号与课程权限 | 登录后只得到本人角色和获准课程；所有文件、对话与结果访问在服务端校验 |
| C02 | 文件保存与阅读 | 上传成功即保留原件；阅读和下载获准文件；解析失败仍可取回原件 |
| C03 | 统一文档解析 | 正文、图片、表格与位置分别保存；明确已读范围、未读内容和失败原因 |
| C04 | 课程上下文 | 从当前页面自动取得课程和材料；切换课程更新会话范围，禁止混入其它课程私人内容 |
| C05 | 进度与失败恢复 | 离开后可找回文件、任务和草稿；重复点击不创建重复任务；失败可以重试 |
| C06 | 可核对的来源 | 知识点、答疑、评分与建议都能追溯实际材料、版本或作业记录 |

现有文件入口支持 PDF、PPT/PPTX、DOCX、PNG/JPG，单文件 20 MB 是原方案边界。9 月 16 日新增了表格处理诉求。建议 Demo 优先验收 PPTX、含图 PDF、DOCX、PNG/JPG 与 XLSX/CSV；旧 PPT、复杂扫描件、公式与图表必须经解析能力矩阵评估，不能仅因扩展名获准就宣称完整支持。

## 3 教师功能

### T01 课程课件共享

教师在课程中上传已有课件，查看处理进度，确认资料的共享范围。学生进入同一课程能阅读和下载当前共享版本；教师私人备课文件不随之公开。资料更新保留版本，旧答疑和旧作业继续指向当时使用的版本。

### T02 AI 辅助备课

教师选择真实材料，点击生成重点、难点、常见误区与讲解建议。结果直接出现在可编辑区域，标明来源和 AI 草稿状态。依据不足时提示补充教学目标，不虚构课程要求。开放式备课讨论可以进入 DSH 对话，但生成与保存不依赖聊天。

### T03 教师答疑卡

支持 AI 起草和手工编辑。每张卡包含问题、适用条件、解释或提示、来源、所属课程及版本。教师确认后才可用于“教师提示”；停用或未确认的卡不带教师背书，也不进入学生检索。学生提问命中卡片时，智能体先采用相关内容，再明确区分模型补充。

### T04 作业与评分依据

教师创建任务，关联课程资料，确认必交任务清单和评分表后发布。AI 可辅助生成要求与评分依据，最终由教师采用。必交任务检查完整性；评分项评价质量，二者分别保存。已有学生提交时，变更评分依据须生成新版本，不覆盖原记录。

### T05 自动评阅与复核

支持单份和小批量处理，教师查看真实报告证据、逐项分数、评语和失败情况。AI 计算后自动产生建议，教师可以改分或整体确认。确认记录教师已复核，具体成绩在确认后对本人学生展示；不得让一个未点击的按钮阻塞资料学习、报告处理和后台建议生成。

### T06 学情反馈与下一轮备课

教师查看任教课程的提交、缺交、补交、处理失败和评分分布。统计数字由程序计算，AI 根据数字与作业证据建议补讲知识点、修改答疑卡或补充课件。采用某条建议后进入原备课编辑位置；经教师采用的新版内容能被学生获得，才完成教学循环。

## 4 学生功能

| 编号 | 功能 | 首版行为 |
| --- | --- | --- |
| S01 | 获取课程资料 | 阅读和下载教师共享课件；自行上传的学习资料默认私人可见 |
| S02 | 多模态伴学 | 在材料旁选择文字、当前页、图片或整份文件提问；能连续追问并查看可定位来源 |
| S03 | 教师提示与知识点 | 查看确认后的答疑卡、结构化知识点与相关页；能分辨教师内容和 AI 补充 |
| S04 | 完成和提交报告 | 查看作业要求，自己完成实验后提交原文件；收到明确缺项时补交，保留历次尝试 |
| S05 | 理解反馈 | 查看本人允许展示的检查结果与学习建议；教师确认后可查看自己的具体成绩、详细评语与依据 |

“整份文件可提问”表示智能体可以检索整份获准资料，不表示所有页面一次性进入模型。读不到的图、超出处理范围的页和不支持的格式必须向学生说明。

## 5 全局 Agent 与 MCP

G01 全局学习指引：学生从自己的课程、作业进度和已允许展示的反馈中获得复习顺序与平台使用帮助。对学习程度的判断需说明依据，不把访问次数当成掌握程度。

G02 全局教学概览：教师查询自己任教课程的作业完成情况，定位需要处理的缺交、失败或共性问题。教师全局 Agent 不读取学生私人聊天。

G03 外部 MCP 接入：开发客户端作为另一种 Agent 入口，调用同一套经权限校验的结构化业务服务。黄山已确认平台内全局 Agent 和外部 MCP 都要在 Demo 前跑通最小示例。具体模型或客户端名字不是功能证明，须通过实际调用演示。

## 6 哪些功能使用对话

对话用于材料伴学、看图解释、追问、开放式备课和全局指引。上传下载、知识点提取、AI 一键生成答疑卡、提交检查、批量评分、数字统计和教师确认通过平台操作完成。用户不必把后台结果从聊天里复制回表单，AI 的固定任务结果直接保存为可编辑、可追溯的业务内容。

现有页面承接上述功能：课程总览与课程页承接 T01/S01，材料工作台承接 T02/T03/S02/S03，作业设置承接 T04，作业与报告页承接 S04/S05/T05，教学反馈承接 T06。全局入口沿用现有导航扩展，不推翻已经完成的课程与资料界面。

## 7 Demo 的最小完整链路

教师上传含图课件，生成并确认一张真实答疑卡；学生在该课程中读图提问并收到可回到原文的回答；教师发布带必交任务和评分依据的作业；学生提交报告并经历一次缺项补交；教师看到逐项评分和证据；系统汇总作业情况，教师采用建议修改答疑卡，学生再次学习时得到新版本内容。

核心教学智能体要展示实际读图、课程上下文与教师提示三个差异点。AutoGrader 最小实现可以只针对一种真实实验场景，但每一步输入和输出都必须真实。全局 Agent 与 MCP 均完成最小真实调用，不能用未运行的接口定义替代演示。

## 8 范围取舍与已确认边界

黄山已确认：基本要求只检查作业归属、任务和附件完整性，不检查质量及格线；学生在教师确认后可看本人详细成绩；未确认不阻塞教师端处理和统计建议；全局 Agent 与 MCP 均完成最小示例。伴学可解释步骤并给示例代码，但不代做实验、编造结果或生成整份可提交报告。

语音输入是此前已确认需求，继续保留，但其上线前提为 HTTPS、可用听写服务和实际录音测试。自测题、复杂知识图谱、连续实时语音对话、完整教务体系、自动生成整套课件和自动代做实验不纳入此次新增开发范围。
